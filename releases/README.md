# 版本规划与仓库分工

## 仓库分工

- `agibot-x2-navigation`：ROS 2 校正、SLAM、定位和导航配置，以及本次 MuJoCo SLAM 集成。
- `x2-simulation-sdk`：SDK 定制、原生仿真启动、网页控制台和真机扫描工作台；保留自己的更新记录与版本号。
- 厂商 AIMDK v1.0.0 是依赖版本，不等于任一社区仓库的发布版本。

保留现有 ROS 包路径和默认/备选实现，避免移动目录破坏 launch、资源路径及用户脚本。
源码在 src/，仿真集成在 simulation/，验证摘要在 docs/validation/，发布材料在 releases/。
地图、rosbag、原始日志、生成场景、build/install 不纳入源码提交；由运行脚本在本机生成。
当前样例地图未发布，复现者需提供自己的 cloud.pcd 和 trajectory.json；原生 X2 模式还需要厂商运行资源。

## 如何分版本

按可复现的功能里程碑发布，日志用于证明该提交通过了哪些检查。每个版本必须固定到提交，
记录依赖、运行命令、验收指标和限制；不能用最新代码冒充多个历史版本。

建议导航仓库首次预发布为 `v0.1.0-alpha.1`，范围见 [草案](v0.1.0-alpha.1.md)。
这是候选编号，尚未创建 tag 或 GitHub Release。SDK 仓库同名候选版本独立管理。

后续规划（均未实现或发布）：

| 版本里程碑 | 发布条件 |
| --- | --- |
| 0.1.x alpha | 修复与补齐当前仿真 SLAM 的复现能力 |
| 0.2.0 alpha | 扫描场景碰撞、保存地图定位与 Nav2 仿真避障通过端到端检查 |
| 1.0.0 | 真机部署、定位与导航完成明确的现场验收，接口与安装流程稳定 |

不要按每条日志或每个小功能建 Release，也暂不拆成更多仓库。
发布时将已审核候选提交打标签，创建 prerelease，使用对应版本说明；不得移动已发布标签。
现有 SDK 仓库的发布失败记录需单独处理，不能把文档中的版本名当作已发布版本。
